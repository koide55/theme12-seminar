# テーマ12：AIに任せるか、人間が決めるか ― インシデント対応AIエージェントの「人間の介在」を設計する

**指導教員**：小出 洋（情報基盤研究開発センター／サイバーセキュリティセンター）
**配属人数**：最大3名　**形式**：実習6コマ＋レポート＋プレゼン

---

## 概要

サイバー攻撃への対応（インシデント対応）にAIエージェントを使う動きが広がっています。アラートを読み、原因を推定し、「このサーバをネットワークから隔離する」といった対処まで、AIが自動で行えるようになりつつあります。

しかし、ここで次のような問題が生じます。

- **すべてAIに任せると**：速いが、誤検知に反応して業務を止めるなどの誤判断が起きる
- **すべて人間が確認すると**：安全だが遅く、担当者が承認作業に追われる

では、**どの判断はAIに任せ、どの判断で人間の承認を挟めばよいのでしょうか。**

本テーマでは、**OpenAI API** を使って、模擬アラートを読んで対応を決めるインシデント対応エージェントを作ります。そのうえで、次の3つの運用方法を比較します。

| 条件 | 内容 |
|---|---|
| **人間中心** | AIは提案するだけ。すべての対応を人間が承認する |
| **完全委譲** | AIがすべて自分で決めて実行する |
| **判断DSL** | 「重要サーバを隔離するときは人間に確認」のような**人間を呼ぶ条件**をルール（判断DSL）で書き、条件に当てはまるときだけ人間が判断する |

実験では、**皆さん自身が「承認者」として参加します**。成功率、誤判断率、人間の介入回数、応答時間を測り、AIと人間の役割分担の最適な設計を探ります。

## こんな人に向いています

- 生成AIを使ったシステムを自分で作ってみたい
- 「AIにどこまで任せてよいか」という問いに興味がある
- サイバーセキュリティの現場の判断を体験してみたい

## 実習内容（6コマ）

| コマ | 内容 | 到達目標 |
|---|---|---|
| 1 | インシデント対応の基礎。OpenAI APIで、模擬アラートを読んで対応を提案するエージェントを作る | APIを呼び出し、AIの提案を構造化された形式（JSON）で受け取れる |
| 2 | 3条件（人間中心・完全委譲・判断DSL）の実装 | 同じシナリオを3条件で実行できる |
| 3 | 判断DSLの設計：どんな条件で人間を呼ぶべきかを各自が考え、ルールとして書く | 自分の設計方針を、根拠を添えてルールで表現できる |
| 4 | 比較実験：模擬インシデント10件 × 3条件 × 反復。学生が承認者役となって判断する | 成功率・誤判断率・介入回数・応答時間を記録できる |
| 5 | 分析：誤判断の分類。ルールを変えるとトレードオフがどう変わるかを調べる | 結果をデータに基づいて説明できる |
| 6 | 考察と発表準備 | 「AIと人間の役割分担」の設計指針を提案できる |

※ 模擬インシデント（模擬アラート・模擬ログと、それぞれの正しい対応）は研究室で用意します。進み具合に応じて、自分たちで新しいシナリオを作る発展課題に取り組みます。

## 成果物

- **レポート**：
  - エージェントの構成
  - 3条件の説明と自分たちが設計した判断DSL
  - 比較実験の結果（表・グラフ）
  - 誤判断の分類
  - 考察（安全性と効率のトレードオフ）
- **プレゼン**：「AIに任せた場合、人間が見た場合、ルールで要所だけ人間が見た場合」の違いを、実験データと具体的な誤判断の例で示す

## 前提知識・準備

- **前提知識**：Pythonの基本。生成AIのAPIやセキュリティの専門知識は不要です（第1コマで説明します）。
- **機材**：ノートPC（Windows / macOS）。**Git、Python 3.10以上、Visual Studio Code を事前にインストールしておいてください。** Windows の人は、PowerShell を管理者として開き、スクリプトの実行を許可する設定（`Set-ExecutionPolicy RemoteSigned`）も必要です。手順は `docs/01_session1.md` の3.0節にあります。
- **APIキー**：OpenAI APIのキーは研究室で用意します。

## 注意事項

- **使うのは模擬データだけです。** 実在の組織のログや個人情報は扱いません。また、AIの「隔離」「遮断」などの対応は、記録上のシミュレーションとしてだけ実行します。実際のシステムやネットワークは操作しません。
- **APIキーは他人に渡さないこと。** GitHubなどの公開の場所にアップロードしたり、プログラムに直接書き込んだりしてはいけません。必ず環境変数で管理してください。
- **API利用料は研究室が負担します。** 大量の繰り返し実行を行う前には、回数と見込み費用を教員に相談してください。
- **承認者の人数は3人と少ないため、結果には個人差が出ます。** それ自体も考察の対象です。
