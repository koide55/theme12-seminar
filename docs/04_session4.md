# 第4回：比較実験 ― あなたが承認者になる

電気情報工学セミナーA　テーマ12「AIに任せるか、人間が決めるか」

**今日のゴール**

1. 公平な比較実験の組み立て方（同じ条件をそろえる、順番の影響を打ち消す）を説明できる
2. 3つの条件（人間中心・完全委譲・判断DSL）で、承認者として10件のアラートを判断できる
3. 正解と照らし合わせて、成功率・誤判断率・介入回数・応答時間を求められる
4. 実験の前に立てた予想と、実際の結果を比べられる

**時間配分の目安（90分）**：説明 15分 → 準備 10分 → 実験 40分 → 採点・集計 15分 → まとめ 10分

## 1. 今日の実験

### 条件と指標

| 条件 | ルールファイル |
|---|---|
| 人間中心 | `rules/human_centered.yaml` |
| 完全委譲 | `rules/full_delegation.yaml` |
| 判断DSL | `rules/team.yaml`（第3回に班で作ったもの） |

| 指標 | 意味 |
|---|---|
| **タスク成功率** | 最終的に実行された対応が正解の範囲に入り、**対象も合っていた**割合 |
| **誤判断率** | 成功しなかった割合（過剰対応、対応不足、対象違いなどに分けて数える） |
| **承認なし実行** | 業務や人への影響が大きく、**人間の承認が必要な対応**を、人間を通さずに実行した件数（**正しい対応でも数える**） |
| **介入回数** | 人間（あなた）が呼ばれた回数（ルールによるもの＋AIの `escalate`） |
| **応答時間** | 1件を処理するのにかかった時間（AIの時間＋あなたの判断時間） |

### 新しいアラート

今日から `data/alerts.json` に **A06〜A10 の5件が加わり、全10件**になります。皆さんにとって初めて見るアラートです。第3回で作ったルールが、**まだ見ていないアラートでも役に立つか**を確かめることも、今日の実験の目的です。

### 公平に比べるための工夫

`s4_run.py` は、次のように動きます。

1. **最初に、すべてのアラートについてAIの提案を作っておきます**（10件 × 2回）。3つの条件では**同じ提案**を使います。条件ごとにAIの答えが変わってしまうと、結果の違いが「条件のせい」なのか「AIのばらつきのせい」なのか分からなくなるからです。
2. **アラートの順番は、条件ごとにばらばらに並べ替えます。**
3. **条件を行う順番は、班の中で人ごとに変えます**（下の表）。最初の条件ではアラートを初めて見ますが、2つ目以降では見たことがあります。この「慣れ」の影響を、班全体で打ち消すためです。

| 班の中で | 条件の順番 | `--order` |
|---|---|---|
| 1人目 | 人間中心 → 完全委譲 → 判断DSL | `HFD` |
| 2人目 | 完全委譲 → 判断DSL → 人間中心 | `FDH` |
| 3人目 | 判断DSL → 人間中心 → 完全委譲 | `DHF` |

（2人の班は `HFD` と `DHF` を使います。）

### 実験の約束

- **班の人と相談しないでください。** 一人ひとりが独立した承認者です。
- **正解は、全員の実験が終わってから配布します。** それまで、ほかの班の結果も見ないでください。
- 本番の承認者になったつもりで、よく読んで判断してください。急ぐ必要はありませんが、考えすぎて止まることもないように。
- 判断の理由は、なるべくひとこと書いてください（第5回の分析で使います）。

## 3. 実験

自分の順番（第1節の表）を確かめて、実行します。

```bash
python s4_run.py --name あなたの名前 --order HFD
```

1. 最初に「AIに提案を作らせています」と表示され、APIの呼び出しが20回行われます（1〜2分）。
2. 条件ごとに「準備ができたら Enter を押してください」と聞かれます。条件の名前を確かめてから始めてください。
3. 操作は第2回と同じです（`y` で承認、`n` で却下して対応を選び直す、理由をひとこと）。
4. 1件ごとに `results/session4_<名前>_<日時>.csv` に保存されます。

途中で止まってしまったら、そこまでの結果は残っています。**最初からやり直さずに、教員に相談してください。**

## 4. 採点・集計

全員の実験が終わったら、教員が正解（`data/answers.json`）を配布します。

```bash

```

まず自分の結果が表示されます。

```

人間中心          20     80%       4             0        20    100%             1               3          18.2         21.0
判断DSL           20     85%       3             0         9     45%             1               1          15.6         10.1
```

（数字は一例です。）続けて、誤判断の種類、承認なし実行の一覧、アラートごとの成功数が表示されます。

- **人間が直した**：AIの提案は誤りだったが、あなたが却下・変更して正解になったもの
- **人間が誤らせた**：AIの提案は正しかったが、あなたが却下・変更して誤りになったもの
- **AI単独の成功**：AIの提案をそのまま実行していたら正解だった数

採点の結果は `results/session4_scored.csv` に保存されます。1件ごとに正誤と誤判断の種類が入っているので、**第5回の分析にそのまま使います。**

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `⚠ アラートが 5 件しかありません` | `git pull` をしていない。`n` で終了してから `git pull` |
