## 1. 分析の見方

### 誤判断の3つの原因

第4回の結果で「成功しなかった」件は、**誰がどこで失敗したか**で3つに分けられます。

| 原因 | 何が起きたか | 減らすには |
|---|---|---|
| **AIの誤りがすり抜けた** | ルールが `auto` にしたため、AIの誤った提案がそのまま実行された | 人間を呼ぶ条件を増やす |
| **人間が誤らせた** | AIは正しかったのに、人間に回して、人間が誤った判断をした | 人間を呼ぶ条件を減らす？　人間に見せる情報を変える？ |
| **人間も直せなかった** | AIが誤り、人間に回したが、人間も誤った | 人間の判断を助ける工夫が要る |

これに加えて、正誤とは別に**承認なし実行**（承認が必要な対応を、人間を通さずに実行した件数）を見ます。

### 4つの物差し

ルールを変えると、次の4つが同時に動きます。**全部を同時に最高にすることはできません。**

- **成功率**：高いほどよい
- **承認なし実行**：少ないほどよい（責任の所在、業務への影響）
- **介入率**：低いほど人間の手間が少ない
- **1件の平均秒**：短いほど速く対応できる（緊急のアラートで大事）

## 4. ステップ2：ルールを変えたらどうなっていたか

`s5_whatif.py` は、**第4回の実験をやり直さずに**、別のルールで運用していたら結果がどうなっていたかを計算します（APIは使いません）。

```bash
python s5_whatif.py rules/team.yaml
```

```
第4回の「人間中心」の結果 40 件（承認者: …）をもとに計算

ルール                  成功率  誤判断  承認なし実行  介入率  1件の平均秒  すり抜け  人間が誤らせた  人間も直せず
人間中心                   75%      10             0    100%         18.2         0               4             6
完全委譲                   70%      12             4      0%          1.1        12               0             0
私たちのルール             78%       9             0     55%         10.4         2               3             4
```

（数字は一例です。）人間中心と完全委譲も、比べるために同じ方法で計算して並べます。続けて、`team.yaml` の**ルールごとに**、何件に使われ、そのうち何件が誤りだったかが表示されます。

> **計算のしかた（大事な仮定）**：ルールが人間を呼んだ件は、その承認者が第4回の「人間中心」で同じ提案に下した判断と時間を使います（人間中心では、すべての提案を判断しているからです）。実際には、判断する件数が減れば疲れにくくなるなど、人間の判断も変わるかもしれません。**この計算は「目安」**です。

### ルールを改良する

`team.yaml` を写して、改良版を作ります。

```bash
cp rules/team.yaml rules/team_v2.yaml          # Windows は copy rules\team.yaml rules\team_v2.yaml
```

`team_v2.yaml` を書き換え、元のルールと並べて比べます。いくつでも並べられます。

```bash
python s5_whatif.py rules/team.yaml rules/team_v2.yaml rules/team_v3.yaml --by-alert
```

`--by-alert` を付けると、アラートごとに成功数がどう変わったかも表示されます。

目標の例（班で1つ選ぶか、自分たちで決める）：

- 承認なし実行を 0 に保ったまま、介入率をできるだけ下げる
- 成功率をできるだけ上げる（介入率は気にしない）
- 1件の平均秒を、人間中心の半分以下にする

> ⚠ **作りすぎに注意**：この10件にぴったり合わせたルールは、別のアラートでは外れるかもしれません（第3回の「型で書く」を思い出しましょう）。改良した理由を、**アラートのIDではなく、アラートの性質で説明できる**かを確かめてください。

結果は `results/session5_whatif.csv` に保存されます。第6回で、グラフを作るのに使います。

## 5. ステップ3：AIが強くなったら、ルールは変わるか

ここまで使ってきたAIは、小さめのモデルです。**より強いモデル**にも同じアラートを判断させ、比べます。**班で1人だけ**実行してください（APIを40回使います）。

```bash
python s5_models.py collect --model gpt-5.4-nano       # 今まで使ってきたモデル（20回）
python s5_models.py collect --model gpt-5.6-terra      # 強いモデル（20回）
```

できたファイル（`results/session5_proposals_*.csv`）を班のメンバーに配ります。各自の `results/` に入れてから、比べます（ここからはAPIを使いません）。

```bash
python s5_models.py compare rules/team.yaml rules/team_v2.yaml rules/full_delegation.yaml
```

表示されるもの：

1. **AI単独**：モデルごとの成功率、承認なし実行、自信の平均（正解のときと誤りのとき）
2. **アラートごと**：どのモデルがどのアラートで誤ったか
3. **ルールを当てはめた場合**：モデルごと・ルールごとの介入率、すり抜け、承認なし実行、止めた誤り、余計な確認（ここでは、人間に回した件は人間が正しく判断したとみなします）

考えるヒント：

- 強いモデルは、どのアラートで小さいモデルと違う答えを出しましたか？
- 強いモデルで**完全委譲**にすると、承認なし実行はどうなりましたか？　「強いAIなら任せてよい」と言えますか？
- 強いモデルを使うなら、あなたたちのルールのどこを変えますか？　変えないほうがよいルールはどれですか？
- 自信（`confidence`）の値は、モデルによってどう違いましたか？　「自信 < 0.7 なら人間」というルールは、どちらのモデルで役に立ちますか？

## 7. 今日のまとめと次回予告

- 誤判断には「AIの誤りがすり抜ける」「人間が誤らせる」「人間も直せない」の3つの原因がありました。
- ルールを変えると、成功率・承認なし実行・介入率・時間が**同時に**動きます。どれを優先するかは、技術だけでは決まりません。
- AIが強くなっても、**承認が要る対応**はなくなりません。
