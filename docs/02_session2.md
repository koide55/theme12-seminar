# 第2回：3つの方式でAIエージェントを動かす

電気情報工学セミナーA　テーマ12「AIに任せるか、人間が決めるか」

**今日のゴール**

1. 「人間中心」「完全委譲」「判断DSL」の3つの方式の違いを説明できる
2. ルールファイルを切り替えて、3つの方式でAIエージェントを動かせる
3. **自分が承認者になって**AIの提案を判断し、その時間と回数を記録できる
4. 3つの方式の結果を集計して、違いを数字で比べられる

**時間配分の目安（90分）**：説明 15分 → 準備 5分 → ステップ1〜4 40分 → コードを読む・演習 25分 → まとめ 5分

## 1. 今日作るしくみ

第1回は「AIに提案させる」ところまででした。今日は、その提案を**実行するかどうかを誰が決めるか**を、プログラムで切り替えられるようにします。

```
 アラート ──▶ AIが提案 ──▶ 判断DSL ──┬─ auto ──────▶ そのまま実行
              (第1回の部品)  （ルール）  │
                                       └─ ask_human ─▶ あなたが承認する？
                                                         │ y：AIの提案を実行
                                                         │ n：あなたが対応を選んで実行
```

- 「実行」はすべて**記録上のシミュレーション**です。実際の機器は一切操作しません。
- AI自身が `escalate`（自分では判断せず人間に引き継ぐ）を選んだときは、どの方式でも**あなたが対応を選びます**。

### 3つの方式

| 方式 | ルールファイル | 人間に確認するとき |
|---|---|---|
| 条件1 人間中心 | `rules/human_centered.yaml` | **すべて** |
| 条件2 完全委譲 | `rules/full_delegation.yaml` | なし（AIが `escalate` を選んだときだけ） |
| 条件3 判断DSL | `rules/example.yaml` | ルールに当てはまるときだけ |

3つの方式は**同じプログラム**で動きます。違うのはルールファイルだけです。ルールの書き方は `docs/dsl_spec.md` にまとめてあります。今日は例のルールを使い、第3回で自分のルールを書きます。

### 何を記録するか

| 記録する項目 | 意味 |
|---|---|
| 人間の確認回数 | あなたが呼ばれた回数（ルールによるものと、AIの `escalate` によるものを分けて数える） |
| 却下・変更 | あなたがAIの提案を退けた回数、最終的な対応がAIの提案と違った回数 |
| 時間 | AIが答えるまでの秒数と、**あなたが判断にかけた秒数** |
| 判断の理由 | あなたが入力したひとこと（任意） |

人間に確認すれば安全そうですが、そのぶん**時間がかかり、人間の手間も増えます**。このトレードオフを数字で見るのが今日の目的です。

## 3. ステップ1：人間中心（すべてあなたが承認する）

```bash
python s2_run.py rules/human_centered.yaml --name あなたの名前
```

アラートとAIの提案が表示され、次のように聞かれます。

```
▶ あなたの承認が必要です。
  この提案を実行してよいですか？ [y/n] >
```

- `y`：AIの提案をそのまま実行します。
- `n`：却下します。続けて、代わりに実行する対応を番号で選び、対象を入力します（Enter で AIと同じ対象）。
- 最後に「判断の理由」をひとこと入力します（Enter で省略可。第5回の分析に使うので、なるべく書きましょう）。

> ⏱ 判断にかかった時間を計っています。ただし、**急ぐ必要はありません。** 本番の承認者になったつもりで、アラートと提案をよく読んでから答えてください。

5件が終わると、確認回数と合計時間が表示され、`results/session2_human_centered_<日時>.csv` に保存されます。

## 4. ステップ2：完全委譲（AIがすべて決める）

```bash
python s2_run.py rules/full_delegation.yaml --name あなたの名前
```

AIの提案が、確認なしでどんどん実行されます。画面に出る `[シミュレーション] ... を実行しました` を読んで、**本当に実行されたら困るものがないか**を見ておきましょう。

## 5. ステップ3：判断DSL（ルールに当てはまるときだけ確認する）

まず、例のルールを読みます。

```bash
python dsl.py rules/example.yaml
```

```
OK: 「判断DSLの例」 ルール 4 個、どれにも当てはまらないときは ask_human
  1. 重要な機器の隔離は人間が確認する  →  ask_human
  2. AIの自信が低いときは人間が確認する  →  ask_human
  3. アカウント停止は人間が確認する  →  ask_human
  4. すぐ元に戻せる対応はAIに任せる  →  auto
```

`rules/example.yaml` をエディタで開き、それぞれのルールがどう書かれているかも見ておきましょう。そのうえで実行します。

```bash
python s2_run.py rules/example.yaml --name あなたの名前
```

人間に確認するときは、**どのルールに当てはまったか**が表示されます。

```
  （人間に確認する理由: ルール「アカウント停止は人間が確認する」）
```

## 7. コードを読む

`s2_run.py` の `handle()` 関数を開き、次の3か所を探してください。

1. AIに提案させているところ（第1回の `propose()` をそのまま使っています）
2. **人間を呼ぶかどうかを決めているところ**（`decide()`。判断DSLの心臓部）
3. あなたが判断にかけた時間を計っているところ（`ask_human()` の中の `time.monotonic()`）

方式を変えても、変わるのは 2 の結果だけだということを確かめましょう。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `ModuleNotFoundError: No module named 'yaml'` | 第2節の `pip install -r requirements.txt` をもう一度実行する（仮想環境が有効か確認） |
| `[ルールの誤り] ...` | 表示されたルールと項目を `docs/dsl_spec.md` と見比べる。字下げはスペース2つ |
| `y か n で答えてください。` | `y` か `n` を半角で入力して Enter |
| 入力を間違えた・途中でやめたい | `Ctrl + C` で中断できます。そこまでの結果は保存されるので、最初からやり直してかまいません（集計のときは、使わないCSVを `results/` から別の場所へ移す） |
| `知らないアラートIDです` | `--alerts A01,A02` のように、カンマ区切り・空白なしで書く |
| `集計するCSVがありません` | `code` フォルダで実行しているか確認する。先に `s2_run.py` を実行する |
| API に関するエラー（`401`、`429` など） | 第1回のトラブルシューティングを参照 |

すべてのAPI呼び出しは、第1回と同じく `code/logs/api_calls.jsonl` に記録されます。
